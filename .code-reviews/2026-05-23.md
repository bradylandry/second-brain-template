## High

### Skills installed to wrong directory — all slash commands broken after `setup.sh`
- **File**: `setup.sh:64-65`
- **Issue**: `setup.sh` creates `$DEST/.claude/skills/` and copies skill files there. However, Claude Code's slash command loader looks in `.claude/commands/`, not `.claude/skills/`. The `integrations/claude-code/README.md` even documents this explicitly: *"Claude Code looks for slash commands in `.claude/commands/`, not `.claude/skills/`."* This means every user who runs `./setup.sh` with the `claude-code` integration gets a vault where `/braindump`, `/challenge`, `/emerge`, `/weekly-review`, and `/onboard-vault` are completely unavailable — silently. This is the core value prop of the claude-code integration.
- **Fix**: Change lines 64-65 of `setup.sh`:
  ```bash
  mkdir -p "$DEST/.claude/commands"
  cp "$SCRIPT_DIR/integrations/claude-code/skills/"*.md "$DEST/.claude/commands/"
  ```
  Update the echo on line 66 to reference `.claude/commands/`.

### `collect_git_activity` never returns commits — shell substitution doesn't work with `subprocess.run`
- **File**: `scripts/narrative_generator.py:62`
- **Issue**: The git log command is invoked as:
  ```python
  subprocess.run(
      ["git", "-C", str(repo), "log", ...,
       "--author=$(git config user.email)"],
      ...
  )
  ```
  Because `subprocess.run` defaults to `shell=False`, the argument `--author=$(git config user.email)` is passed **literally** to git — the shell substitution never runs. Git receives the string `$(git config user.email)` as an author regex, which matches no real email addresses (the `$` anchors to end-of-string and the parentheses are regex groups that don't match typical author fields). The function always returns `"(no git activity)"` regardless of how many commits were made, rendering the git activity section of every generated journal entry useless.
- **Fix**: Resolve the user's git email in Python before passing it to subprocess:
  ```python
  import subprocess
  email_result = subprocess.run(
      ["git", "config", "user.email"],
      capture_output=True, text=True, check=False, timeout=5
  )
  author_email = email_result.stdout.strip()
  # then pass: f"--author={author_email}" if author_email else None
  ```

## Medium

### `setup.sh` hardcodes throwaway git identity for initial vault commit
- **File**: `setup.sh:105`
- **Issue**: The initial commit in every new vault is made as:
  ```bash
  git -c user.email="you@example.com" -c user.name="you" commit -q -m "Scaffold..."
  ```
  This overrides whatever git identity the user has configured globally. Every user's vault history starts with a commit attributed to `you@example.com`. While this is just the first commit, it's visible in `git log` forever and is confusing — especially for users who push their vault to a private GitHub remote where the ghost author shows up in the commit graph.
- **Fix**: Remove the `-c` overrides and let git use the ambient config:
  ```bash
  git commit -q -m "Scaffold second-brain vault from template" || true
  ```
  If the user has no global git identity set, the commit will fail with a helpful git error rather than silently succeeding with wrong authorship.
