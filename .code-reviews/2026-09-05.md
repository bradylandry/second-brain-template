## High

### `multiline_prompt` silently discards all input — Quick Context always empty

- **File**: `vault/research-skill-graph/new-project.sh:30-35`
- **Issue**: The `multiline_prompt` function collects lines into `$joined`, then calls `printf -v "$var_name" '%s' "$value"`. The variable `$value` is never assigned inside `multiline_prompt` — it is only defined (locally) inside the separate `prompt` function. The result is that `$CONTEXT` is always set to an empty string, regardless of what the user types. The generated `index.md` `## Quick Context` section will always be blank.
- **Fix**: Change `"$value"` to `"$joined"` on the `printf -v` line:
  ```bash
  printf -v "$var_name" '%s' "$joined"
  ```

## Medium

### `--author` filter in `collect_git_activity` is a no-op (shell expansion suppressed by `shell=False`)

- **File**: `scripts/narrative_generator.py:59-66`
- **Issue**: The argument `"--author=$(git config user.email)"` is passed as a literal string element of a list to `subprocess.run` with `shell=False`. Python passes it verbatim to `execvp`; no shell expansion occurs. Git receives the literal regex `$(git config user.email)`, which in regex terms matches "end-of-string" followed by the literal text `git config user.email` — effectively matching nothing. All commits are returned regardless of author, so the function returns other contributors' work alongside the user's.
- **Fix**: Resolve the email before building the argument list:
  ```python
  email_result = subprocess.run(
      ["git", "-C", str(repo), "config", "user.email"],
      capture_output=True, text=True, check=False, timeout=5,
  )
  author_email = email_result.stdout.strip()
  args = ["git", "-C", str(repo), "log",
          f"--since={day} 00:00", f"--until={day} 23:59",
          "--pretty=format:%s"]
  if author_email:
      args.append(f"--author={author_email}")
  out = subprocess.run(args, capture_output=True, text=True, check=False, timeout=10)
  ```

## Low

### `new-project.sh` index.md update inserts after only the first line of the `## 4. Active Projects` section

- **File**: `vault/research-skill-graph/new-project.sh:136-147`
- **Issue**: The `awk` script looks for `## 4. Active Projects`, prints that heading, reads one `nextline`, prints it, and then inserts the new entry. If the heading is followed by existing project entries (not just a blank line), the new entry is inserted after the very first line, not at the end of the list. This produces an inconsistently ordered list and may interleave entries in surprising ways.
- **Fix**: Append the entry after the entire block. A simpler approach is to use `sed` to insert after the heading line rather than consuming one lookahead line, or collect the whole section and append at the bottom. Alternatively, append to a dedicated marker line rather than relying on positional insertion:
  ```bash
  sed -i "/^## 4\. Active Projects/a $ENTRY" "$ROOT_INDEX"
  ```
  Note: this inserts immediately after the heading (not after existing entries), which is consistent and predictable regardless of current list size. If bottom-of-list ordering is required, replace the awk block with an explicit end-of-section marker in the template.
