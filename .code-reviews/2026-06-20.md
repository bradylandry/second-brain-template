## High

### Shell expansion literal in argv — git author filter never matches
- **File**: `scripts/narrative_generator.py:62`
- **Issue**: The `--author` argument is `"--author=$(git config user.email)"`. Because this is passed as an element of a Python list (not a shell string), `$(git config user.email)` is never expanded — git receives the literal characters `$(git config user.email)` as the author pattern. The author filter therefore matches nothing, so every repo always returns zero commits regardless of the user's actual git email.
- **Fix**: Resolve the author email before constructing the subprocess call:
  ```python
  email_result = subprocess.run(
      ["git", "-C", str(repo), "config", "user.email"],
      capture_output=True, text=True, check=False
  )
  author_email = email_result.stdout.strip()
  # then pass f"--author={author_email}" if author_email else omit the flag
  ```

### `setup.sh` installs skills to wrong path — slash commands will not work
- **File**: `setup.sh:64-65`
- **Issue**: The installer creates `$DEST/.claude/skills/` and copies skill files there. Claude Code resolves slash commands from `.claude/commands/`, not `.claude/skills/`. The `integrations/claude-code/README.md` (line 25) documents this distinction explicitly, but `setup.sh` was never updated to match. Any user who runs `./setup.sh ~/my-vault claude-code` will get no working slash commands (`/braindump`, `/challenge`, etc.).
- **Fix**: Change lines 64-65 in `setup.sh`:
  ```bash
  mkdir -p "$DEST/.claude/commands"
  cp "$SCRIPT_DIR/integrations/claude-code/skills/"*.md "$DEST/.claude/commands/"
  ```
  Also update the echo on line 66 accordingly. Separately, `docs/getting-started.md:88` says "skills in `.claude/skills/`" — update that too.

### `narrative_generator.py` silently overwrites existing journal entries
- **File**: `scripts/narrative_generator.py:159,169`
- **Issue**: `out_path.write_text(body)` unconditionally overwrites any existing file at `journal/YYYY-MM-DD.md`. If the script is run twice in one day (e.g., once in the evening and once after midnight for the same date), or if the user has already written a manual journal entry for that day, it is silently lost. There is no check, backup, or append mode.
- **Fix**: Add an existence check before writing:
  ```python
  if out_path.exists() and not args.dry_run:
      print(f"Warning: {out_path} already exists. Use --force to overwrite.", file=sys.stderr)
      sys.exit(1)
  ```
  Add a `--force` flag if the caller wants to regenerate. Alternatively, append to the file rather than overwriting.

### `setup.sh` tilde expansion only works for the interactive prompt path, not the CLI arg
- **File**: `setup.sh:16,21`
- **Issue**: `DEST="${DEST/#\~/$HOME}"` (line 21) only runs inside the `if [[ -z "$DEST" ]]` block (interactive prompt). When a user passes `~/my-vault` as the first command-line argument (the documented usage in the README), the tilde is not expanded, and `DEST` remains literally `~/my-vault`. Whether this breaks depends on the shell — bash expands tildes in unquoted arguments before the script sees them, but some invocations (e.g., from another script) may not. The fix is cheap and defensive.
- **Fix**: Apply tilde expansion unconditionally after setting DEST:
  ```bash
  DEST="${1:-}"
  DEST="${DEST/#\~/$HOME}"
  ```

### `new-project.sh` uses a temp file without cleanup on failure
- **File**: `vault/research-skill-graph/new-project.sh:148`
- **Issue**: The awk pipeline writes to `$ROOT_INDEX.tmp` and then moves it into place. If the `awk` command exits non-zero (e.g., disk full, awk not found), the `.tmp` file is left on disk. Under `set -euo pipefail`, the script will abort, but the orphaned temp file may confuse subsequent runs or editors.
- **Fix**: Add a trap to clean up on failure:
  ```bash
  trap 'rm -f "$ROOT_INDEX.tmp"' EXIT
  ```
  Place before the awk call, remove after the mv succeeds.
