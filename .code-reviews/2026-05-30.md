## High

### `--author=$(git config user.email)` never expands — git activity collection silently broken

- **File**: `scripts/narrative_generator.py:65`
- **Issue**: The git subprocess call passes `"--author=$(git config user.email)"` as a literal string element in a Python list with `shell=False` (the default). Python's `subprocess.run` passes that string verbatim to git without invoking a shell, so git receives the literal text `$(git config user.email)` as the author pattern. No real commit author matches this string, so the `--author` filter silently excludes all commits and git activity always returns `"(no git activity)"`. The function appears to work (no exception) but produces no output.
- **Fix**: Resolve the email before constructing the argument list:
  ```python
  email = subprocess.run(
      ["git", "-C", str(repo), "config", "user.email"],
      capture_output=True, text=True, check=False
  ).stdout.strip()
  args = ["git", "-C", str(repo), "log",
          f"--since={day} 00:00", f"--until={day} 23:59",
          "--pretty=format:%s"]
  if email:
      args.append(f"--author={email}")
  ```

### No error handling around `client.messages.create()` — script crashes on API failure with no output

- **File**: `scripts/narrative_generator.py:103-107`
- **Issue**: The Anthropic API call is unwrapped. Any error — network failure, rate limit, invalid or expired API key, model unavailability — raises an unhandled exception. The script exits with a traceback, nothing is written to the journal, and users have no recovery path or informative error message.
- **Fix**: Wrap the API call in a try/except and print a human-readable message before exiting:
  ```python
  try:
      result = client.messages.create(...)
  except Exception as e:
      print(f"LLM call failed: {e}", file=sys.stderr)
      sys.exit(1)
  ```
  Consider also adding `--dry-run` output of the collected context as a diagnostic path when the LLM step fails.

## Medium

### Generated vault `.gitignore` omits `.env` and secret-file patterns

- **File**: `setup.sh:53-61`
- **Issue**: The `.gitignore` written into the new vault by `setup.sh` covers `.DS_Store`, Obsidian state, editor swap files, and Python virtualenvs — but omits `.env`, `.env.local`, `*secret*`, and `*credentials*`. Users who create a `.env` file to hold `ANTHROPIC_API_KEY` (as the narrative generator requires), or who store API tokens anywhere in the vault, could accidentally commit those secrets if they push to a public remote. The template's own repo `.gitignore` has all these entries, but they are not propagated to the scaffolded vault.
- **Fix**: Add to the heredoc in `setup.sh`:
  ```
  .env
  .env.local
  *.env
  *secret*.json
  *credentials*.json
  ```

### No dependency spec — users must guess `pip install anthropic`

- **File**: `scripts/narrative_generator.py:1` (module level)
- **Issue**: The script requires the `anthropic` package but the repo ships no `requirements.txt`, `pyproject.toml`, or `setup.cfg`. The README comment mentions `pip install anthropic` but that only guards against the package being absent — it doesn't pin a version, which means breaking API changes in future SDK releases will silently affect users. The `client.messages.create()` call surface changed once already (between SDK 0.x and 1.x).
- **Fix**: Add a minimal `scripts/requirements.txt`:
  ```
  anthropic>=0.40,<1.0
  ```
  Or a `pyproject.toml` with `[project.optional-dependencies]`. Reference it in the README.

## Low

### Initial vault commit uses placeholder git identity

- **File**: `setup.sh:72`
- **Issue**: `git -c user.email="you@example.com" -c user.name="you" commit` hardcodes generic placeholder credentials for the first commit. Users who don't notice this will have `you@example.com` as the author of every early vault commit. It's a cosmetic issue but looks unprofessional in git logs and can confuse tools that filter by author email.
- **Fix**: Drop the `-c` overrides and let git use the system identity (`git config user.email`). If git identity might not be configured in fresh environments, add a check and prompt the user before the commit.

### Default model `claude-sonnet-4-5` is outdated

- **File**: `scripts/narrative_generator.py:104`
- **Issue**: `os.environ.get("NARRATIVE_MODEL", "claude-sonnet-4-5")` defaults to `claude-sonnet-4-5`, which is a prior-generation model. Current generation is `claude-sonnet-4-6`. The env override mitigates, but users who don't set `NARRATIVE_MODEL` will silently use an older model that may be retired.
- **Fix**: Update the default to `"claude-sonnet-4-6"` (or `"claude-opus-4-8"` for higher quality journal entries).
