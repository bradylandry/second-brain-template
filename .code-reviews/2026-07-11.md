## High

### Broken git author filter — `$()` not shell-expanded, git always returns no commits
- **File**: `scripts/narrative_generator.py:61`
- **Issue**: The git log command passes `"--author=$(git config user.email)"` as a literal list element to `subprocess.run`. Because `shell=False` (the default when passing a list), the shell never evaluates `$(git config user.email)` — it is passed verbatim to git as the author pattern. Git treats it as a regex, and since no author's email address literally matches the string `$(git config user.email)`, zero commits are returned every time. `collect_git_activity` silently returns `"(no git activity)"` even when the day had commits. The journal entry is generated without any git context, defeating a core feature.
- **Fix**: Resolve the email before building the argument list:
  ```python
  email_result = subprocess.run(
      ["git", "-C", str(repo), "config", "user.email"],
      capture_output=True, text=True, check=False,
  )
  author_email = email_result.stdout.strip()
  # then in the log command:
  *([f"--author={author_email}"] if author_email else []),
  ```

## Medium

### Skills glob in `setup.sh` will abort setup if no `.md` files exist
- **File**: `setup.sh:65`
- **Issue**: `cp "$SCRIPT_DIR/integrations/claude-code/skills/"*.md "$DEST/.claude/skills/"` is called under `set -euo pipefail`. If the glob matches nothing (e.g., if the integration directory is empty or renamed), bash expands the pattern literally to a non-existent path and `cp` exits non-zero. With `set -e` active, this immediately terminates `setup.sh` with no useful error message. The user ends up with a partially scaffolded vault and no clear indication of what went wrong. By contrast, the analogous Python copy at line 87 correctly uses `2>/dev/null || true`.
- **Fix**: Apply the same pattern: `cp "$SCRIPT_DIR/integrations/claude-code/skills/"*.md "$DEST/.claude/skills/" 2>/dev/null || true`. Alternatively, add `shopt -s nullglob` at the top of the case block.

## Low

### Default model name `claude-sonnet-4-5` is outdated
- **File**: `scripts/narrative_generator.py:124`
- **Issue**: The default value of `NARRATIVE_MODEL` is `claude-sonnet-4-5`. This is a reference implementation intended to be copied into users' vaults; users who don't set the environment variable will hit a model-not-found error (or get an older model) without understanding why. Current Anthropic models include `claude-sonnet-5` and `claude-haiku-4-5-20251001`.
- **Fix**: Update the default to `claude-sonnet-5` (or `claude-haiku-4-5-20251001` for a cheaper default appropriate to a local script). Add a brief comment noting the env var override so it's easy to pin to a specific version.

### `awk` temp file not cleaned up on failure
- **File**: `vault/research-skill-graph/new-project.sh:148`
- **Issue**: `awk ... > "$ROOT_INDEX.tmp" && mv "$ROOT_INDEX.tmp" "$ROOT_INDEX"` leaves `$ROOT_INDEX.tmp` behind if `awk` writes a partial output then the script exits (e.g., via `set -e` on a subsequent command). The temp file is benign — it won't be read by anything — but it's noise in the vault index directory.
- **Fix**: Add a `trap 'rm -f "$ROOT_INDEX.tmp"' EXIT` near the top of the script, or use `sponge` from moreutils to do an in-place rewrite without a temp file.

### Placeholder identity in initial git commit
- **File**: `setup.sh:105`
- **Issue**: `git -c user.email="you@example.com" -c user.name="you" commit ...` creates the first vault commit with placeholder author info. If the user's global git config already has their real identity, using `-c` overrides it. The result is an initial commit attributed to `you <you@example.com>` which can be confusing (especially if they later push their vault to a private remote).
- **Fix**: Drop the explicit `-c user.email` and `-c user.name` overrides so git uses the user's existing global config. If a guard against missing identity is needed: `git commit -q -m "Scaffold second-brain vault from template" 2>/dev/null || git -c user.email="setup@vault" -c user.name="setup" commit -q -m "Scaffold second-brain vault from template"`.
