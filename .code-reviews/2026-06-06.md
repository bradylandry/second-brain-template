## High

### Git `--author` filter never matches — `collect_git_activity` always returns "(no git activity)"
- **File**: `scripts/narrative_generator.py:60-68`
- **Issue**: The git log call is:
  ```python
  ["git", "-C", str(repo), "log",
   f"--since={day} 00:00", f"--until={day} 23:59",
   "--pretty=format:%s", "--author=$(git config user.email)"],
  ```
  Because `subprocess.run` is called with a **list** (not `shell=True`), the `$()` in `--author=$(git config user.email)` is passed **literally** to git as the author regex. No email address ever matches the literal string `$(git config user.email)`, so the filter always returns zero commits. The function silently returns `"(no git activity)"` even on days with heavy commit activity, and the narrative generator then skips the git section entirely.
- **Fix**: Resolve the user email before building the command:
  ```python
  result = subprocess.run(
      ["git", "-C", str(repo), "config", "user.email"],
      capture_output=True, text=True, check=False, timeout=5,
  )
  author_email = result.stdout.strip() or None
  
  cmd = ["git", "-C", str(repo), "log",
         f"--since={day} 00:00", f"--until={day} 23:59",
         "--pretty=format:%s"]
  if author_email:
      cmd.append(f"--author={author_email}")
  ```

## Medium

### Default model ID is one generation behind the current Claude API
- **File**: `scripts/narrative_generator.py:125`
- **Issue**: `model=os.environ.get("NARRATIVE_MODEL", "claude-sonnet-4-5")` — the hardcoded default is `claude-sonnet-4-5`, which is the previous model generation. The current generation is `claude-sonnet-4-6` (as of 2026-06-06). Users who install and run the script without setting `NARRATIVE_MODEL` silently get inferior output quality.
- **Fix**: Update the default:
  ```python
  model=os.environ.get("NARRATIVE_MODEL", "claude-sonnet-4-6"),
  ```

### No error handling around the Anthropic API call
- **File**: `scripts/narrative_generator.py:116-128`
- **Issue**: The `llm_narrate` function calls `client.messages.create(...)` with no try/except. If the API is rate-limited, returns an auth error, or times out, the exception propagates to `main()` uncaught, exiting with a Python traceback. For a reference script this is acceptable, but the README describes wiring this into an automated nightly pipeline (`scripts/narrative_generator.py`), where silent crashes lose journal entries.
- **Fix**: Wrap the API call:
  ```python
  try:
      result = client.messages.create(...)
  except Exception as e:
      print(f"LLM call failed: {e}", file=sys.stderr)
      sys.exit(1)
  ```
  At minimum this makes the failure explicit and distinct from the `ImportError` path above it.

## Low

### Initial vault commit uses placeholder git identity
- **File**: `setup.sh:72-73`
- **Issue**: `git -c user.email="you@example.com" -c user.name="you" commit -q -m "Scaffold second-brain vault from template"` — the first commit in every vault is attributed to `you@example.com / you`, regardless of the user's configured git identity. Users who later `git log` their vault see a spurious commit from a phantom author.
- **Fix**: Remove the `-c user.email` and `-c user.name` overrides so git uses the user's global config. If git identity might not be set, detect it first and prompt or warn:
  ```bash
  if git -C "$DEST" commit -q -m "Scaffold second-brain vault from template" 2>/dev/null; then
    echo "✓ Initialized git repo (first commit made)"
  else
    echo "⚠ Git commit skipped — configure git user.email/user.name first"
  fi
  ```

### `chmod +x` and `cp scripts` errors are silently swallowed
- **File**: `setup.sh:70` and `setup.sh:83-84`
- **Issue**: Both `chmod +x "$DEST/research-skill-graph/new-project.sh" 2>/dev/null || true` and `cp "$SCRIPT_DIR/scripts/"*.py "$DEST/scripts/" 2>/dev/null || true` suppress all errors. If `new-project.sh` lacks execute permission or the scripts copy fails, the user gets no indication — they discover the problem later when trying to use the tool.
- **Fix**: Remove the `2>/dev/null || true` suppression, or at least print a warning on failure:
  ```bash
  chmod +x "$DEST/research-skill-graph/new-project.sh" || \
    echo "⚠ Could not make new-project.sh executable — run: chmod +x $DEST/research-skill-graph/new-project.sh"
  ```
