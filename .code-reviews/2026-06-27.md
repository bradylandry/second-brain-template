## High

### 1. `--author` filter is a no-op — all contributors' commits are included in the narrative

- **File**: `scripts/narrative_generator.py:62`
- **Issue**: The git subprocess is called with `subprocess.run([..., "--author=$(git config user.email)"])` and `shell=False` (the default). Because there is no shell, `$(git config user.email)` is passed as a literal string to git — git's `--author` regex then matches only authors whose email literally contains `$(git config user.email)`, which is nobody. The filter silently fails and `git log` returns every commit in the date range from all contributors.
- **Fix**: Resolve the author email before the subprocess call and interpolate it:
  ```python
  email_result = subprocess.run(
      ["git", "-C", str(repo), "config", "user.email"],
      capture_output=True, text=True, check=False, timeout=5,
  )
  author_email = email_result.stdout.strip()
  author_flag = [f"--author={author_email}"] if author_email else []
  out = subprocess.run(
      ["git", "-C", str(repo), "log",
       f"--since={day} 00:00", f"--until={day} 23:59",
       "--pretty=format:%s"] + author_flag,
      ...
  )
  ```

### 2. Journal entry is silently overwritten if re-run on the same day

- **File**: `scripts/narrative_generator.py:169`
- **Issue**: `out_path.write_text(body)` unconditionally overwrites `journal/YYYY-MM-DD.md`. A user who hand-edited the generated entry (or ran the script twice to capture an afternoon update) silently loses their edits. There is no prompt, no backup, and no `--force` guard.
- **Fix**: Add an existence check before writing. Either exit with an informative error, append instead of overwrite, or add a `--force` / `--append` flag:
  ```python
  if out_path.exists() and not args.force:
      print(f"Journal entry already exists: {out_path}. Use --force to overwrite.", file=sys.stderr)
      sys.exit(1)
  ```

### 5. Scaffolded vault git commit uses a hardcoded dummy identity

- **File**: `setup.sh:105`
- **Issue**: The initial commit in the scaffolded vault is made as `user.email="you@example.com"` / `user.name="you"`, hardcoded via `-c` flags. If the user hasn't configured a global git identity, this produces a first commit attributed to a dummy author. Subsequent commits from the user will have a different identity, creating a confusing blame history. This is minor on private vaults but can surprise users.
- **Fix**: Remove the `-c` overrides and let git use its configured identity. If no identity is configured, git will fail with a clear error prompting the user to configure one, which is better than silently setting a dummy identity:
  ```bash
  git commit -q -m "Scaffold second-brain vault from template" || true
  ```

### 6. Model identifier `claude-sonnet-4-5` may be stale

## Low

### 7. `setup.sh` tilde expansion only handles leading `~` — paths like `~/sub/../other` are unhandled

- **File**: `setup.sh:21`
- **Issue**: `DEST="${DEST/#\~/$HOME}"` expands a leading `~` but does not call `realpath` or equivalent, so paths with `..` components or symlinks aren't normalized. This is an edge case (most users type `~/my-vault`) but could produce unexpected behavior if the path resolves differently than the user expects.
- **Fix**: Add `DEST="$(realpath -m "$DEST")"` (or `python3 -c "import os,sys; print(os.path.expanduser(sys.argv[1]))" "$DEST"` for cross-platform safety) after the tilde expansion.

### 8. `new-project.sh` awk edit of `index.md` does not preserve a trailing newline reliably

- **File**: `vault/research-skill-graph/new-project.sh:140-148`
- **Issue**: The awk script that injects a project entry into `research-skill-graph/index.md` writes to a `.tmp` file and renames it. The awk idiom used (`getline nextline` + reprint) is correct in most awks but may drop the trailing newline on some POSIX awks. Minor, but can cause `git diff` noise (no newline at end of file).
- **Fix**: Add `END { if (substr($0, length($0)) != "\n") printf "\n" }` to the awk script, or pipe through `printf '%s\n' "$(cat "$ROOT_INDEX.tmp")"` before the move. Alternatively, rely on the `|| true` and note this is cosmetic.
