## Medium

### `--author` filter silently collects all commits instead of filtering by user
- **File**: `scripts/narrative_generator.py:59-64`
- **Issue**: The git log command is built as a Python list and passed to `subprocess.run` with `shell=False` (the default). The argument `"--author=$(git config user.email)"` is therefore passed as a **literal string** to git — the shell never expands `$(...)`. Git's `--author` filter then tries to match the literal regex pattern `$(git config user.email)`. The `$` anchor and parentheses make this an odd regex that matches no real commit authors. Depending on git version this either returns zero commits or silently ignores the flag — either way, the intended per-user filtering never works. The function's `collect_git_activity` is the core data source for the journal entry, so the LLM receives either nothing or everyone's commits on shared repos.
- **Fix**: Pre-fetch the email with a separate subprocess call and pass the resolved value:
  ```python
  email_proc = subprocess.run(
      ["git", "config", "user.email"],
      capture_output=True, text=True, check=False, timeout=5,
  )
  author_email = email_proc.stdout.strip()
  cmd = ["git", "-C", str(repo), "log",
         f"--since={day} 00:00", f"--until={day} 23:59",
         "--pretty=format:%s"]
  if author_email:
      cmd.append(f"--author={author_email}")
  out = subprocess.run(cmd, capture_output=True, text=True, check=False, timeout=10)
  ```

## Low

### Default model name is outdated
- **File**: `scripts/narrative_generator.py:124`
- **Issue**: The default model is hardcoded as `"claude-sonnet-4-5"`. The current production Sonnet model is `claude-sonnet-4-6`. Since this is a reference implementation that users will clone and run, they'll silently call a non-current model unless they set `NARRATIVE_MODEL` explicitly.
- **Fix**: Update the default: `model=os.environ.get("NARRATIVE_MODEL", "claude-sonnet-4-6")`.

### Fragile awk insertion in `new-project.sh` when the Active Projects section is empty
- **File**: `vault/research-skill-graph/new-project.sh:136-150`
- **Issue**: The awk script that inserts a new project entry into `research-skill-graph/index.md` reads one line ahead after matching `## 4. Active Projects`. If the section has no entries yet and the next line is immediately another `##` heading, awk prints that heading **before** the new entry, displacing it outside the correct section. The tmp-file swap (`> $ROOT_INDEX.tmp && mv`) also leaves a stale `.tmp` file on partial failures.
- **Fix**: Use a simpler sed insertion: `sed -i "/^## 4\. Active Projects/a\\$ENTRY" "$ROOT_INDEX"` which appends immediately after the matched line without consuming the next line.

### Hardcoded fake author identity in scaffolded vault's initial commit
- **File**: `setup.sh:104-105`
- **Issue**: The initial git commit in the new vault uses `-c user.email="you@example.com" -c user.name="you"`. Every vault's first commit forever attributes to a fake identity, which can be confusing when pushing to a personal remote (GitHub shows `you@example.com` as a contributor).
- **Fix**: Omit the `-c` overrides and let git read from the user's existing `git config`. If no config is set yet, git will prompt naturally:
  ```bash
  git -C "$DEST" commit -q -m "Scaffold second-brain vault from template" || true
  ```
