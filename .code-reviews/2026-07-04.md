## High

### `--author` filter is never evaluated; git activity collection is permanently broken
- **File**: `scripts/narrative_generator.py:60`
- **Issue**: `subprocess.run` is called with a list (no `shell=True`), so `--author=$(git config user.email)` is passed verbatim as a single argument to git. Git log receives the literal pattern `$(git config user.email)` and matches zero commits — because no real author string looks like that. The `commits` list is always empty, `collect_git_activity` always returns `"(no git activity)"`, and if repos are the only configured source the script exits early with `sys.exit(1)`. The git activity section of every narrative is silently empty.
- **Fix**: Resolve the email before building the command list:
  ```python
  email_result = subprocess.run(
      ["git", "-C", str(repo), "config", "user.email"],
      capture_output=True, text=True, check=False,
  )
  author_email = email_result.stdout.strip()
  cmd = ["git", "-C", str(repo), "log",
         f"--since={day} 00:00", f"--until={day} 23:59",
         "--pretty=format:%s"]
  if author_email:
      cmd.append(f"--author={author_email}")
  out = subprocess.run(cmd, capture_output=True, text=True, check=False, timeout=10)
  ```

## Low

### Default model is outdated
- **File**: `scripts/narrative_generator.py:124`
- **Issue**: The hardcoded default `"claude-sonnet-4-5"` is an older model. New installs using the default get a less capable model without realizing it; the most capable current option is `claude-sonnet-5`.
- **Fix**: Update the default to `"claude-sonnet-5"` (or `"claude-opus-4-8"` if quality matters more than cost). The `NARRATIVE_MODEL` env override already lets users pin whichever model they want.

### Initial vault commit uses placeholder git identity
- **File**: `setup.sh:96`
- **Issue**: The first commit in the user's new vault is attributed to `you@example.com` / `you`. While harmless (it's their private repo), it looks odd in `git log` and can confuse tools that filter by author email. If the user's global git config is already set, there is no reason to override it.
- **Fix**: Remove the `-c user.email=...` and `-c user.name=...` overrides so `git commit` inherits the user's actual configured identity. If no global identity is set, git will error helpfully — which is better than silently inserting a placeholder.
