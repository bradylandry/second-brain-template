## Medium

### `--author=$(git config user.email)` is a shell substitution that never runs — git activity is always empty
- **File**: `scripts/narrative_generator.py:59-64`
- **Issue**: `subprocess.run` is called with a list (not `shell=True`), so `$(git config user.email)` is passed as a literal string to `git log --author`. Git interprets it as a POSIX ERE regex: `$` is an end-of-line anchor, followed by `(git config user.email)`. This regex cannot match any real author string, so the `--author` filter silently returns zero commits from every repo in `REPOS_TO_SCAN`. The `collect_git_activity` function will always return `"(no git activity)"`, meaning the context passed to the LLM never contains any actual commit data.
- **Fix**: Fetch the email in a separate subprocess call and interpolate it:
  ```python
  def _git_user_email(repo: Path) -> str:
      result = subprocess.run(
          ["git", "-C", str(repo), "config", "user.email"],
          capture_output=True, text=True, check=False, timeout=5,
      )
      return result.stdout.strip()

  # in collect_git_activity, replace the --author line:
  email = _git_user_email(repo)
  args = ["git", "-C", str(repo), "log",
          f"--since={day} 00:00", f"--until={day} 23:59",
          "--pretty=format:%s"]
  if email:
      args.append(f"--author={email}")
  out = subprocess.run(args, ...)
  ```

### Hardcoded `claude-sonnet-4-5` is a retired model — script fails for users who haven't set `NARRATIVE_MODEL`
- **File**: `scripts/narrative_generator.py:124`, `integrations/generic/README.md` (code example block)
- **Issue**: `claude-sonnet-4-5` is not in the current Claude 4.x model lineup (current Sonnet is `claude-sonnet-4-6`). Users who clone this template and run `narrative_generator.py` without setting the `NARRATIVE_MODEL` env var will get an API error. The generic integration README example has the same stale model ID, which trips up users following the manual pattern.
- **Fix**: Update the default in `narrative_generator.py`:
  ```python
  model=os.environ.get("NARRATIVE_MODEL", "claude-sonnet-4-6"),
  ```
  Update the code block in `integrations/generic/README.md` to match. Document `NARRATIVE_MODEL` in the README quickstart so users know they can override it.

## Low

### Invalid `--integration` argument silently skips AI wiring with no error
- **File**: `setup.sh:51-71`
- **Issue**: The `case "$INTEGRATION"` block has no `*` fallback. If a user invokes `./setup.sh ~/vault foobar`, the case falls through silently — no AI integration is wired, no error is printed, and setup exits successfully. The user gets a vault with no AI config and no indication something went wrong.
- **Fix**: Add a catch-all:
  ```bash
  *)
    echo "Error: unknown integration '$INTEGRATION'. Choose: claude-code, cursor, continue-dev, opencode, generic" >&2
    exit 1
    ;;
  ```

### Initial git commit in new vault uses placeholder author credentials
- **File**: `setup.sh:87`
- **Issue**: `git -c user.email="you@example.com" -c user.name="you" commit -q -m "Scaffold second-brain vault from template"` hard-codes placeholder credentials. The initial commit in the user's private vault repo will show `you <you@example.com>` as author, which is jarring and may cause confusion when the user later runs `git log`.
- **Fix**: Omit the `-c` overrides and let git use the system-configured identity. If git isn't configured (a realistic edge case for new setups), detect it and skip the commit with a friendly message rather than leaving a placeholder:
  ```bash
  if git config user.email >/dev/null 2>&1; then
    git add . && git commit -q -m "Scaffold second-brain vault from template" || true
    echo "✓ Initialized git repo (first commit made)"
  else
    echo "ℹ git user not configured — skipped initial commit. Run 'git commit' after setting git config user.email."
  fi
  ```
