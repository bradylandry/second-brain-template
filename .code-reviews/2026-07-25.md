## High

### setup.sh installs skills to wrong directory, breaking all Claude Code slash commands
- **File**: `setup.sh:64-65`
- **Issue**: The claude-code integration case copies skills to `$DEST/.claude/skills/`, but the integration's own README explicitly states "Claude Code looks for slash commands in `.claude/commands/`, not `.claude/skills/`." Every user who runs `./setup.sh <dest> claude-code` (or picks option 1 at the prompt) ends up with skill files at the wrong path. Claude Code does not load them as slash commands. `/braindump`, `/challenge`, `/emerge`, `/weekly-review`, and `/onboard-vault` are all silently absent — no error, no warning. The failure is invisible to the user.
- **Fix**: Change lines 64-65 in `setup.sh` to use `.claude/commands/` instead of `.claude/skills/`:
  ```bash
  mkdir -p "$DEST/.claude/commands"
  cp "$SCRIPT_DIR/integrations/claude-code/skills/"*.md "$DEST/.claude/commands/"
  ```

### narrative_generator.py git activity always returns empty due to unexpanded shell substitution
- **File**: `scripts/narrative_generator.py:64`
- **Issue**: The `--author` flag is passed as the literal string `"--author=$(git config user.email)"` inside a Python list to `subprocess.run` (no `shell=True`). The OS execs git directly; no shell ever evaluates `$(...)`. Git receives the filter `$(git config user.email)` as a regex pattern, which matches no commit author. The function always silently returns empty output, making the "Git activity" section of every generated narrative entry permanently blank regardless of how many commits were made that day. This is the primary data source the generator was designed around.
- **Fix**: Resolve the user's git email in Python before constructing the subprocess call:
  ```python
  author_result = subprocess.run(
      ["git", "config", "user.email"],
      capture_output=True, text=True, check=False, timeout=5,
  )
  author_email = author_result.stdout.strip()
  # Then use:
  *(["--author", author_email] if author_email else []),
  ```
  Alternatively, remove the `--author` filter entirely if the intent is to capture all commits in a repo regardless of author.

### Default model ID in narrative_generator.py may be stale
- **File**: `scripts/narrative_generator.py:124`
- **Issue**: `os.environ.get("NARRATIVE_MODEL", "claude-sonnet-4-5")` defaults to `claude-sonnet-4-5` without a version suffix. Unversioned model aliases can be deprecated or re-pointed to newer versions with different behavior. As of the review date (2026-07-25) this alias may no longer resolve. The `NARRATIVE_MODEL` env var override mitigates, but first-time users running without it will encounter a silent fallback to whatever the alias currently points to, or an API error if the alias is retired.
- **Fix**: Default to a versioned model ID (e.g., `claude-sonnet-4-5-20251015` or whatever is current), or add a comment directing users to update before running.

### Research project stub headings are lowercase, inconsistent with example project
- **File**: `vault/research-skill-graph/new-project.sh:127`
- **Issue**: The stub output files are created with the heading `# ${name//-/ } — $TITLE`, which produces lowercase section names: `# executive summary — ...`, `# deep dive — ...`, `# key players — ...`, `# open questions — ...`. The example project at `vault/research-skill-graph/projects/example-act-prep-market/` uses title-cased headings. New users scaffolding their first project get subtly wrong-looking stub files compared to the documented example.
- **Fix**: Apply simple title-casing in the heredoc heading. One approach: replace `${name//-/ }` with a shell pipeline: `$(echo "${name//-/ }" | awk '{for(i=1;i<=NF;i++) $i=toupper(substr($i,1,1)) substr($i,2)} 1')`.
