## Medium

### `--author=$(git config user.email)` never expands — git activity always empty
- **File**: `scripts/narrative_generator.py:63`
- **Issue**: `subprocess.run` is called **without** `shell=True`, so the argument `"--author=$(git config user.email)"` is passed to git as a literal string. Git interprets it as a filter for commits whose author contains the verbatim text `$(git config user.email)`, which matches nothing. The git activity section will always produce `"(no git activity)"` regardless of how many commits were made, silently making the daily narrative incomplete.
- **Fix**: Resolve the email before constructing the argument list:
  ```python
  import subprocess
  email_result = subprocess.run(
      ["git", "config", "user.email"], capture_output=True, text=True, check=False
  )
  author_email = email_result.stdout.strip()
  # then in the log call:
  *([f"--author={author_email}"] if author_email else []),
  ```
  Or remove the `--author` filter entirely if multi-author repos are not a concern.

## Low

### User input injected into YAML frontmatter without sanitization in `new-project.sh`
- **File**: `vault/research-skill-graph/new-project.sh:73`
- **Issue**: User-supplied values (`$QUESTION`, `$SCOPE_IN`, `$SCOPE_OUT`, etc.) are interpolated directly into a heredoc that produces YAML frontmatter:
  ```bash
  cat > "$PROJECT_DIR/index.md" <<EOF
  ---
  type: research-project
  created: $TODAY
  ---
  ## Research Question
  $QUESTION
  ```
  A question containing `---` (YAML document separator) or backtick sequences will produce malformed frontmatter that may confuse downstream tools (Obsidian, YAML parsers). This is a personal-use script so the risk is low, but it could break a research project index silently.
- **Fix**: Strip or escape `---` from user inputs, or wrap values in `printf '%q'` before embedding. Alternatively, write frontmatter separately from body using a YAML-aware tool, or document in the prompt that `---` should be avoided.
