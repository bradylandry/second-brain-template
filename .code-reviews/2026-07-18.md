## High

### Git activity collection is silently broken in narrative_generator.py

- **File**: `scripts/narrative_generator.py:59-65`
- **Issue**: The `--author` git flag is constructed as `"--author=$(git config user.email)"` and passed as a list element to `subprocess.run()` with `shell=False` (the default). Because there is no shell involved, the `$(git config user.email)` subshell expression is never evaluated — git receives it as the literal string `$(git config user.email)` and treats it as an author pattern. No real commit author will ever match this pattern, so `collect_git_activity()` always returns `"(no git activity)"` regardless of how many commits were made that day. The feature is completely non-functional and fails silently.
- **Fix**: Resolve the user email in a separate subprocess call first, then interpolate:
  ```python
  email_result = subprocess.run(
      ["git", "-C", str(repo), "config", "user.email"],
      capture_output=True, text=True, check=False, timeout=5,
  )
  author_email = email_result.stdout.strip()
  # then pass f"--author={author_email}" to the log command
  ```
  Alternatively, omit the `--author` filter entirely if the repos are personal (single-author), which is the typical second-brain use case.

## Medium

### Generated vault `.gitignore` omits secrets patterns

- **File**: `setup.sh:93-103`
- **Issue**: `setup.sh` writes a new `.gitignore` to the scaffolded vault using a heredoc. That heredoc is missing several patterns that the template's own root `.gitignore` includes: `.env`, `.env.local`, `*secret*.json`, `*credentials*.json`. Users running `narrative_generator.py` commonly export `ANTHROPIC_API_KEY` (or equivalent) to a `.env` file inside the vault directory. Without the `.env` exclusion, those secrets are committed on the first `git add .` — which `setup.sh` itself runs on line 104.
- **Fix**: Add the missing patterns to the heredoc:
  ```
  .env
  .env.local
  *secret*.json
  *credentials*.json
  .trash/
  *.swo
  ```
  The simplest fix is to `cp "$SCRIPT_DIR/.gitignore" "$DEST/.gitignore"` instead of writing a trimmed version by hand, so the two files stay in sync going forward.

### awk `-v` variable injection can silently corrupt index.md

- **File**: `vault/research-skill-graph/new-project.sh:138-149`
- **Issue**: The variable `$ENTRY` (composed of `$TITLE` and `$QUESTION`, both free-form user text) is passed to awk via `-v entry="$ENTRY"`. The awk `-v` assignment interprets backslash escape sequences: a user who types `\n`, `\t`, or `\\` in their project title or research question will produce a mangled entry in `research-skill-graph/index.md`. The temp-file/move pattern is safe, but the content corruption is silent — the script exits 0 and reports "Created: …" even with a bad entry.
- **Fix**: Pipe the entry through stdin instead of `-v`, where awk does not interpret escapes:
  ```bash
  ENTRY="- [[projects/$SLUG/index]] — $TITLE: $QUESTION"
  awk -v slug="projects/$SLUG/index" '
    BEGIN { entry = "'"$ENTRY"'" }  # or read from ENVIRON
    /^## 4\. Active Projects/ { ... }
  ' ...
  ```
  A more robust fix is to use Python or a simple `sed` append rather than awk for this single-line insertion.

### No pre-flight check for ANTHROPIC_API_KEY

- **File**: `scripts/narrative_generator.py:122`
- **Issue**: `anthropic.Anthropic()` reads `ANTHROPIC_API_KEY` from the environment but raises a non-descriptive `AuthenticationError` (or similar SDK exception) if the variable is unset. Users new to the script will see a raw SDK traceback rather than a clear instruction.
- **Fix**: Add a short check before constructing the client:
  ```python
  if not os.environ.get("ANTHROPIC_API_KEY"):
      print("Error: ANTHROPIC_API_KEY is not set. Export it before running.", file=sys.stderr)
      sys.exit(1)
  ```

### No guard on API response content array

- **File**: `scripts/narrative_generator.py:128`
- **Issue**: `result.content[0].text` raises `IndexError` if the API returns an empty content list (e.g., a stop-reason of `max_tokens` with no partial output, or a safety refusal). This is a reference script, so the risk is low, but it surfaces as an opaque Python traceback.
- **Fix**: Add a guard:
  ```python
  if not result.content:
      print("LLM returned empty content. Exiting.", file=sys.stderr)
      sys.exit(1)
  return result.content[0].text.strip()
  ```

### `mv ./*` glob includes `.` and `..` in shell documentation

- **File**: `docs/mobile.md:35` and `docs/mobile.md:62`
- **Issue**: Both move-your-vault examples use `mv "$SOURCE"/.* "$DEST/"` which expands to include `.` (current directory) and `..` (parent directory). The errors are suppressed with `2>/dev/null`, but shellcheck (SC2224) flags this pattern and some environments produce confusing output. The note in the doc correctly explains this, but newer users may be surprised or adapt the snippet to a context where error suppression isn't present.
- **Fix**: Use `find` or enable `dotglob` before the glob:
  ```bash
  shopt -s dotglob
  mv "$SOURCE"/* "$DEST/"
  shopt -u dotglob
  ```
  This moves hidden files without matching `.` and `..`.
